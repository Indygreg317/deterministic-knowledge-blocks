# Glossary

## Audit Package

A reviewer-facing package that organizes the artifacts, commands, verification summary, and review boundaries needed to inspect a deterministic evaluation chain.

An Audit Package organizes evidence. It does not replace verification or certify production readiness.

## Canonical Hash

A stable artifact identity generated by parsing JSON, sorting object keys, removing insignificant whitespace, preserving array order, and hashing the canonical UTF-8 bytes with SHA-256.

A Canonical Hash supports artifact identity. It does not prove upstream truth or safety.

## Decision Contract

A structured artifact that defines what is being evaluated, which fields are in scope, what operator applies, what threshold applies, and which decision should be produced on pass or fail.

## Deterministic Evaluation

The act of applying explicit, repeatable rules to a structured input artifact.

The source system may remain uncertain or probabilistic. The downstream evaluation rule is deterministic.

## Evaluator Policy

A structured artifact that defines allowed decisions, receipt requirements, review conditions, failure behavior, and audit behavior.

## Execution Receipt

A structured artifact recording the decision claimed by the deterministic evaluator, including referenced artifacts, computed values, status, evaluator identity, and supporting hashes.

A receipt is not evidence merely because it exists. It becomes useful evidence when it survives verification.

## Failure Mode Library

A collection of executable negative examples showing how deterministic receipt verification detects invalid or unsupported cases.

Examples include tampered thresholds, stale hashes, missing input evidence, wrong evaluator identity, and unsupported operators.

## Governance Boundary Map

A structured artifact that separates what artifacts declare from what preserved evidence and deterministic verification can actually test.

The boundary map prevents the system from overstating what verification proves.

## Knowledge Block

A governed decision unit that binds inputs, constraints, contracts, runtime rules, receipts, verification reports, governance boundary maps, audit packages, and verification requirements into a reusable evaluation structure.

## Preserved Artifact

A stored artifact used for replay, verification, inspection, or audit review.

Examples include structured input artifacts, Decision Contracts, Evaluator Policies, Execution Receipts, Verification Reports, and Governance Boundary Maps.

## Receipt Verification

A deterministic replay check that compares an Execution Receipt against preserved artifacts, canonical hashes, and the recomputed outcome.

Receipt verification produces `VALID_RECEIPT`, `INVALID_RECEIPT`, or `UNSUPPORTED_RECEIPT`.

## Structured Input Artifact

A preserved input object submitted to the deterministic evaluation layer.

In the Bell-state example, this is the quantum-output-style probability distribution.

## UNSUPPORTED_RECEIPT

A verification result meaning that the reference verifier cannot independently evaluate the receipt because the referenced contract, operator, or verification pattern is unsupported.

Unsupported is not valid. Unsupported is not invalid. It means the verifier cannot decide.

## Verification Report

A structured evidence artifact recording what receipt was checked, which artifacts and fields were compared, what decision was recomputed, and which mismatches were found.

## Verifier Boundary

The explicit scope of what a verifier can test using preserved artifacts, deterministic rules, and supported verification methods.

Claims outside the verifier boundary should not be presented as proven by the verifier.
